# 一、定价参数

## `pricing_method = "depth_weighted"`

含义：用五档盘口加权中间价作为基准价。

它不是简单用：

```text
(bid1 + ask1) / 2
```

而是结合五档买卖价格和挂单量，算出更贴近盘口结构的 fair price。你的代码里 `PricingEngine.calculate_fair_price()` 会根据 `pricing_method` 选择 `mid`、`micro` 或 `depth_weighted`，其中 `depth_weighted` 会调用五档加权计算逻辑。

影响：

```text
更稳定；
更适合你现在有五档 Level2 数据的情况；
比 mid 更能反映盘口深度。
```

这个参数目前建议保留。

---

## `pricing_depth = 5`

含义：计算五档加权基准价时，看前 5 档盘口。

影响：

```text
设成 1 或 2：
    更敏感，但容易被局部挂单扰动。

设成 5：
    更稳定，能利用完整五档盘口。
```

你现在有上期所五档数据，所以 `5` 合理。

---

# 二、报价参数

## `quote_mode = "tick"`

含义：报价距离按照 tick 数计算。

比如 `spread_tick = 2`，就是基准价上下各偏移 2 个最小价格跳动。

影响：

```text
tick 模式适合期货；
percent 模式更适合价格差异很大的资产，比如股票、币圈。
```

期货做市建议继续用 `tick`。

---

## `quote_levels = 1`

含义：买边挂 1 档，卖边挂 1 档。

影响：

```text
更小：
    风险暴露小，库存积累慢。

更大：
    成交机会多，但更容易在单边行情里连续被打，库存风险更大。
```

你现在改成 1 档后效果变好，说明当前策略更适合“少挂、精选盘口”。

---

## `order_volume = 1`

含义：每笔委托 1 手。

影响：

```text
设成 1：
    单笔风险小，适合调试和初期回测。

设成 2 或更大：
    盈亏都会放大，仓位更快触发 hedge。
```

现在还在调策略，不建议加大。

---

## `spread_tick = 2`

含义：第一档报价距离基准价 2 个 tick。

你的报价逻辑本质是：

```text
买价 = fair_price - spread_tick * price_tick
卖价 = fair_price + spread_tick * price_tick
```

影响：

```text
spread_tick 小，比如 1：
    报价更贴近盘口，成交更多，但容易成交质量差。

spread_tick 大，比如 3：
    报价更远，成交减少，但成交质量可能更好。
```

你现在 `2` 是比较稳健的数值。

---

## `level_interval_tick = 1`

含义：多档报价时，每一档之间间隔 1 个 tick。

但你现在：

```python
quote_levels = 1
```

所以这个参数暂时不太发挥作用。

如果以后 `quote_levels = 2`，那么：

```text
第一档：±2 tick
第二档：±3 tick
```

---

## `spread_percent = 0.0002`

含义：百分比报价模式下第一档距离。

但是你现在：

```python
quote_mode = "tick"
```

所以这个参数暂时不生效。

---

## `level_interval_percent = 0.0001`

同理，只有 `quote_mode = "percent"` 时才生效。

现在不用管。

---

# 三、拆单与重挂参数

## `split_count = 1`

含义：每一档不拆单，只发一笔。

影响：

```text
设成 1：
    订单数量少，逻辑清楚。

设大：
    同一档会拆成多笔，订单数量变多，总暴露也变大。
```

现在建议保持 1。

---

## `update_tolerance = 2`

含义：新旧报价差距超过 2 个 tick，才撤单重挂。

影响：

```text
设小，比如 1：
    报价更灵敏，但撤单重挂频繁。

设大，比如 3：
    订单挂得更久，但可能旧报价已经不合适。
```

你现在是半秒级 Tick 数据，盘口跳动快，`2` 是比较合理的折中。

---

# 四、盘口过滤参数

这部分是你现在收益变好的关键。

## `min_depth = 5`

含义：要求买卖五档都有效，才允许做市。

影响：

```text
设成 1 或 3：
    过滤宽松，更多时间可以做市。

设成 5：
    过滤严格，只在盘口完整时做市。
```

你现在 `5` 很严格，说明你只在 Level2 数据质量完整时交易。

---

## `min_spread_tick = 2`

含义：市场买卖价差至少要有 2 个 tick，才允许报价。

影响：

```text
设成 1：
    机会更多，但价差空间小。

设成 2：
    只在价差更宽的时候做，利润空间更好，但成交机会减少。
```

这个参数很关键。做市利润来自价差，如果价差太窄，手续费和对冲成本容易吃掉利润。

---

## `depth_check_level = 5`

含义：检查盘口深度和不平衡时，看前 5 档。

影响：

```text
设成 1：
    只看买一卖一，很敏感但片面。

设成 5：
    看完整五档，更稳定。
```

你现在用 5 合理。

---

## `min_depth_volume = 50`

含义：前五档买盘总量、卖盘总量都至少 50 手，才做市。

影响：

```text
设小，比如 20 / 30：
    过滤宽松，成交机会更多。

设大，比如 50：
    过滤严格，只在盘口较厚的时候做。
```

你现在 `50` 比之前的 `30` 更保守，能减少被薄盘口打穿的风险。

---

## `max_imbalance = 0.1`

含义：盘口买卖力量必须非常均衡。

盘口不平衡计算大概是：

```text
imbalance = (买盘总量 - 卖盘总量) / (买盘总量 + 卖盘总量)
```

你现在要求：

```text
abs(imbalance) <= 0.1
```

也就是说，五档买卖盘总量不能明显偏向一边。

影响：

```text
设成 0.7：
    比较宽松，很多盘口都能做。

设成 0.3：
    比较严格。

设成 0.1：
    非常严格，只在买卖盘很均衡时做。
```

这个参数现在非常保守。它可能是你效果变好的重要原因，因为它避开了明显单边盘口。

但缺点是：交易机会会少很多。

---

# 五、库存控制参数

## `max_position = 4`

含义：最大净持仓 4 手。

影响：

```text
设小：
    库存风险小，但交易空间有限。

设大：
    给库存更多回转空间，但单边行情回撤更大。
```

你现在是偏保守设置。

---

## `max_skew_tick = 2`

含义：库存偏移最多移动 2 个 tick。

你的库存偏移逻辑是：

```text
多头仓位偏多：
    买卖报价整体下移，减少继续买入，鼓励卖出。

空头仓位偏多：
    买卖报价整体上移，减少继续卖出，鼓励买入。
```

影响：

```text
设成 1：
    库存修正温和。

设成 2：
    当前比较平衡。

设成 3：
    库存修正更强，但可能让报价变远、成交减少。
```

现在 2 合理。

---

# 六、强制对冲参数

## `enable_hedge = True`

含义：启用强制平仓/对冲。

建议保持 True。做市策略如果没有库存兜底，容易在单边行情里越积越偏。

---

## `hedge_threshold = 4`

含义：净持仓达到 4 手时触发强制对冲。

你现在：

```python
max_position = 4
hedge_threshold = 4
```

这表示仓位达到最大限制时才强制对冲。

影响：

```text
hedge_threshold 小：
    更早对冲，风险低，但可能过早止损。

hedge_threshold 大：
    给库存回转空间，但风险更大。
```

这里我提醒你一下：如果想更稳，可以考虑：

```python
hedge_threshold = 3
```

如果你现在回测结果很好，就先保持 4。

---

## `hedge_volume = 1`

含义：每次强制对冲 1 手。

影响：

```text
设成 1：
    温和，慢慢降仓。

设成 2：
    降仓更快，但可能在不利价格上平太多。
```

现在仓位上限只有 4，所以 `hedge_volume = 1` 合理。

---

## `hedge_price_tick = 0`

含义：强制平仓不额外穿价。

```text
多头平仓：卖在 bid1
空头平仓：买在 ask1
```

如果设成 1：

```text
多头平仓：bid1 - 1 tick
空头平仓：ask1 + 1 tick
```

影响：

```text
0：
    对冲价格更好，但成交速度可能慢一点。

1：
    更容易成交，但每次多损失 1 tick。
```

你现在用 0 是合理的，因为之前强平成本可能比较伤收益。

---

# 七、成交后处理参数

## `cancel_on_trade = True`

含义：普通做市单成交后，撤掉剩余普通挂单，等待下一次 tick 重新报价。

影响：

```text
True：
    更稳健，成交后重新评估盘口和库存。

False：
    订单留得更久，可能增加双边成交机会，但旧报价风险更大。
```

做市策略建议保持 True。

---

# 八、被动报价参数

## `passive_quote = True`

含义：保持被动挂单，不主动吃单。

代码里会限制：

```text
买价不能高于 bid1
卖价不能低于 ask1
```

影响：

```text
True：
    更像真实做市，靠挂单赚价差。

False：
    更容易成交，但会变成偏主动交易，成本和滑点压力更大。
```

你现在做的是做市策略，建议保持 True。

---

# 这组参数的整体风格

你现在这组参数可以命名为：

```text
严格过滤型盘口做市参数
```

它的特点是：

```text
1. 用 depth_weighted 做基准价；
2. 只挂 1 档，减少暴露；
3. 报价距离 2 tick，提高成交质量；
4. 只在五档完整时交易；
5. 只在价差至少 2 tick 时交易；
6. 要求前五档深度至少 50 手；
7. 要求盘口极度均衡，max_imbalance 只有 0.1；
8. 最大仓位 4 手，控制库存风险；
9. 强制对冲不额外穿价，降低对冲成本。
```

这就是为什么它更准、更稳：**它不是更激进了，而是更挑交易环境了。**
