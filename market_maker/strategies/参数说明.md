可以，你这组参数我按**功能链路**给你完整解释一遍。你现在的策略参数其实可以分成 8 类：

```text
1. 定价参数：决定报价中心在哪里
2. 报价参数：决定挂几档、离基准价多远、每单几手
3. 重挂参数：决定多久撤单重挂
4. 盘口过滤参数：决定什么行情允许做市
5. 库存控制参数：决定仓位偏了怎么调报价
6. 强制对冲参数：决定仓位失控时怎么平仓
7. 成交后处理参数：决定成交后是否撤旧单
8. 被动报价参数：决定是否主动吃单
```

你的代码流程是：`on_tick()` 里先更新盘口，然后做行情风控过滤，再算 `fair_price`，再生成买卖报价，之后做库存偏移、仓位过滤、判断是否需要撤单重挂，最后发普通做市单；成交后在 `on_trade()` 里检查是否触发强制对冲。

# 一、定价参数

## 1. `pricing_method: str = "depth_weighted"`

这个参数决定**基准价怎么计算**。

你现在用：

```python
pricing_method = "depth_weighted"
```

意思是用五档盘口加权中间价作为做市基准价。

你的策略里支持三种：

```text
mid：
    只看 bid1 和 ask1 的中间价。

micro：
    看 bid1 / ask1 和买一卖一数量。

depth_weighted：
    看五档买卖价格和五档挂单量。
```

影响：

```text
mid：
    最简单，但容易忽略盘口压力。
    如果买卖盘量差异很大，mid 可能太钝。

micro：
    比 mid 更敏感，能反映买一卖一量的压力。
    但只看一档，容易被一档挂单扰动影响。

depth_weighted：
    利用五档深度，更平滑，也更适合你现在有 Level2 五档数据的场景。
    你回测发现它效果更好，说明五档深度对你的报价中心有帮助。
```

所以这个参数目前不建议改，继续用：

```python
pricing_method = "depth_weighted"
```

这个参数决定 `depth_weighted` 看几档盘口。

你现在：

```python
pricing_depth = 5
```

意思是用买一到买五、卖一到卖五计算加权中间价。

影响：

```text
变小，比如 1 或 2：
    基准价更敏感，更贴近当前盘口。
    但容易被短期挂单扰动影响。

变大，比如 5：
    基准价更稳定，能反映更完整的盘口结构。

```

你现在有五档数据，所以 `5` 是合理的。

# 二、报价参数

## 3. `quote_mode: str = "tick"`

这个参数决定报价距离怎么计算。

你现在：

```python
quote_mode = "tick"
```

意思是按照最小变动价位 tick 来报价。

比如 `price_tick = 1`，`spread_tick = 2`，那么第一档买价就是：

```text
fair_price - 2
```

第一档卖价就是：

```text
fair_price + 2
```

如果改成：

```python
quote_mode = "percent"
```

那就会用百分比方式，比如距离基准价 `0.02%`。

影响：

```text
tick 模式：
    更适合期货盘口做市。
    因为期货最小跳动单位明确，比如 1、2、0.2。

percent 模式：
    更适合股票、币圈、价格跨度很大的资产。
    对你现在这个期货盘口策略不是首选。
```

所以你现在用 `tick` 是对的。

## 16. `max_imbalance: float = 0.70`

你现在：


影响：

```text
变小，比如 0.60：
    更严格。
    盘口稍微偏一边就不做。
    风险更低，但机会更少。

变大，比如 0.80 或 0.90：
    更宽松。
    成交机会更多。
    但容易在单边盘口中继续挂单。
```

你现在做市策略最怕单边行情，所以这个参数非常关键。
