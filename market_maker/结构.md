这段代码整体就是一个 **“Order 模式双边做市策略”**：每来一个 tick 行情，就计算基准价，然后生成买卖两边报价，再根据库存偏移、风控过滤、是否需要撤单重挂，最后发出 `buy/short` 双边挂单；成交后可以选择撤单，并按库存阈值做主动对冲。代码主体是 `OrderMarketMakerStrategy(CtaTemplate)`，其他类都是给它服务的模块。

---

## 一、最核心的运行流程

你先记住一句话：

> **行情进来 → 检查行情风险 → 算基准价 → 生成双边报价 → 库存偏移 → 持仓风控 → 判断是否重挂 → 撤旧单 → 发新单 → 成交后可对冲**

对应代码主要在 `on_tick()` 里面。

---

## 二、整体模块分工

### 1. `MarketDataManager`

这个模块负责把 tick 行情整理成统一格式。

它会保存：

```python
bid_prices
ask_prices
bid_volumes
ask_volumes
bid1
ask1
market_spread
valid_depth
```

也就是把 vn.py 的 `TickData` 变成一个 `snapshot` 字典，方便后面所有模块使用。

你可以理解为：

> 原始行情清洗器。

比如它会算：

```python
market_spread = ask1 - bid1
valid_depth = 有效盘口深度
```

---

### 2. `PricingEngine`

这个模块负责算 **fair_price / 基准价**。

目前支持三种方式：

```python
pricing_method = "mid"
pricing_method = "micro"
pricing_method = "depth_weighted"
```

分别对应：

| 方法               | 含义               |
| ---------------- | ---------------- |
| `mid`            | 买一卖一中间价          |
| `micro`          | 根据买一卖一挂单量加权的微观价格 |
| `depth_weighted` | 多档盘口加权中间价        |

核心就是这个：

```python
self.fair_price = self.pricing_engine.calculate_fair_price(...)
```

你这个策略后面的所有报价，都是围绕 `fair_price` 展开的。

---

### 3. `QuoteEngine`

这是做市报价模块。

它根据 `fair_price` 生成买卖双边报价。

比如：

```python
fair_price = 100
price_tick = 1
spread_tick = 1
quote_levels = 3
```

那么它可能生成：

```text
买一档：99
买二档：98
买三档：97

卖一档：101
卖二档：102
卖三档：103
```

也就是：

> 基准价下方挂买单，基准价上方挂卖单。

它支持两种报价方式：

### 第一种：tick 模式

```python
quote_mode = "tick"
```

价格按照最小跳动单位等差展开：

```python
offset_tick = spread_tick + (level - 1) * level_interval_tick
```

这个就是你之前说的 **等差报价**。

---

### 第二种：percent 模式

```python
quote_mode = "percent"
```

价格按照百分比偏离基准价：

```python
raw_buy_price = fair_price * (1 - offset_percent)
raw_sell_price = fair_price * (1 + offset_percent)
```

这个就是你之前说的 **按比例报价**。

---

### 4. `InventorySkewEngine`

这是库存偏移模块。

作用是：

> 根据当前持仓，让报价整体往某个方向移动，避免库存越积越多。

假如你现在是多头：

```python
pos > 0
```

说明你已经买多了，不想继续买太多，希望多卖少买。

代码里做法是：

```python
adjusted_buy_quotes = move down
adjusted_sell_quotes = move down
```

也就是双边报价都往下移。

效果是：

买单价格更低，不容易继续买入；
卖单价格也更低，更容易卖出去减仓。

反过来，如果你是空头：

```python
pos < 0
```

它会把报价整体往上移：

买单更高，更容易买回来平空；
卖单更高，不容易继续卖空。

这个模块很重要，因为它体现了做市商不是无脑双边挂单，而是要控制库存。

---

### 5. `HedgeEngine`

这是主动对冲模块。

它不在 `on_tick()` 里主动运行，而是在：

```python
on_trade()
```

里面运行。

也就是说：

> 只有成交发生后，才检查是否需要对冲。

逻辑是：

```python
if pos >= hedge_threshold:
    SELL_CLOSE
```

如果多头太多，就卖出平仓。

```python
if pos <= -hedge_threshold:
    BUY_CLOSE
```

如果空头太多，就买入平仓。

注意这里不是普通开仓，是：

```python
self.sell()
self.cover()
```

在 vn.py 语义里通常对应 **平多 / 平空**。

---

### 6. `QuoteRiskFilter`

这是报价前风控模块。

在 `on_tick()` 里，它会连续检查：

```python
check_market_data
check_depth
check_spread
check_depth_volume
check_imbalance
filter_by_position
```

含义大概是：

| 风控        | 作用              |
| --------- | --------------- |
| 行情是否合法    | bid/ask 是否正常    |
| 深度够不够     | 是否有足够盘口         |
| 价差够不够     | spread 太小不报价    |
| 深度挂量够不够   | 流动性太差不报价        |
| 买卖盘是否极端失衡 | 防止一边倒行情         |
| 持仓是否超限    | 多头满了不再买，空头满了不再卖 |

这个模块的逻辑是：

> 不适合做市的时候，直接撤单。

---

## 三、真正的主线在 `OrderMarketMakerStrategy`

其他模块都是工具，真正控制策略运行的是这个类：

```python
class OrderMarketMakerStrategy(CtaTemplate):
```

最核心的是这几个事件函数：

```python
on_init()
on_start()
on_stop()
on_tick()
on_order()
on_trade()
```

你理解顺序应该是：

```text
on_start → on_tick → on_order → on_trade
```

---

## 四、最重要的是 `on_tick()`

你要重点理解 `on_tick()`，因为它是整个策略的心脏。

每次行情更新，都会执行：

### 第一步：更新行情

```python
snapshot = self.market_data.update_tick(tick)
```

把 tick 变成标准化盘口快照。

---

### 第二步：更新界面变量

```python
self.bid1 = snapshot["bid1"]
self.ask1 = snapshot["ask1"]
self.market_spread = snapshot["market_spread"]
self.valid_depth = snapshot["valid_depth"]
```

这些是显示在 vn.py 策略界面里的变量。

---

### 第三步：做风控检查

只要有一个条件不过，就：

```python
self.cancel_all()
self.quote_engine.clear_current_quotes()
return
```

也就是说：

> 行情不合格，撤掉所有报价，不做市。

---

### 第四步：计算基准价

```python
self.fair_price = self.pricing_engine.calculate_fair_price(...)
```

这是后面报价的核心。

---

### 第五步：生成双边报价

```python
buy_quotes, sell_quotes = self.quote_engine.generate_quotes(...)
```

这里会生成买单列表和卖单列表。

这一步生成的是理论报价，还没有考虑库存。

---

### 第六步：库存偏移

```python
buy_quotes, sell_quotes = self.inventory_skew_engine.apply_skew(...)
```

这一步根据当前 `self.pos` 调整报价。

如果你多头偏多，就鼓励卖出；
如果你空头偏多，就鼓励买回。

---

### 第七步：持仓限制

```python
buy_quotes, sell_quotes = self.quote_risk_filter.filter_by_position(...)
```

如果：

```python
pos >= max_position
```

就不再挂买单。

如果：

```python
pos <= -max_position
```

就不再挂卖单。

---

### 第八步：判断是否需要重新报价

```python
if not self.quote_engine.need_requote(...):
    return
```

这个是为了避免每个 tick 都疯狂撤单重挂。

如果新报价和旧报价差别不大，就不重挂。

---

### 第九步：撤旧单，发新单

```python
self.cancel_all()
```

然后：

```python
self.buy(...)
self.short(...)
```

注意这里是：

```python
for quote in buy_quotes:
    self.buy(...)
```

挂买开仓单。

```python
for quote in sell_quotes:
    self.short(...)
```

挂卖开仓单。

所以这是标准的 **双边开仓报价**。

---

## 五、`on_trade()` 是成交后的逻辑

当某个做市单成交后，会执行：

```python
on_trade()
```

里面第一步：

```python
self.trade_count += 1
```

然后如果配置：

```python
cancel_on_trade = True
```

就会：

```python
self.cancel_all()
self.quote_engine.clear_current_quotes()
self.active_orderids.clear()
```

意思是：

> 一旦有成交，先撤掉其他挂单，避免旧报价继续暴露风险。

然后如果：

```python
enable_hedge = True
```

就检查是否需要主动对冲。

比如多头超过阈值：

```python
SELL_CLOSE
```

然后发：

```python
self.sell(...)
```

如果空头超过阈值：

```python
BUY_CLOSE
```

然后发：

```python
self.cover(...)
```

## 六、你从哪里开始理解最好？

我建议你不要从第一行开始看。最好的顺序是：

---

## 第一优先：先看 `on_tick()`

这是主流程。

你先别管每个模块内部细节，只要理解这条主线：

```text
行情来了
↓
检查能不能报价
↓
算 fair_price
↓
生成 buy_quotes / sell_quotes
↓
根据库存调整报价
↓
判断是否需要重挂
↓
撤单
↓
发买单和卖单
```

你把 `on_tick()` 看懂，整个策略就懂了 60%。

---

## 第二优先：看 `QuoteEngine.generate_quotes()`

因为这是做市策略的核心。

你要搞清楚：

```python
fair_price
spread_tick
level_interval_tick
quote_levels
split_count
order_volume
```

这些参数怎么影响最后的报价。

最核心是这个：

```python
buy_price = fair_price - offset_tick * price_tick
sell_price = fair_price + offset_tick * price_tick
```

你能手算几组报价，就彻底懂了。

---

## 第三优先：看 `PricingEngine`

也就是基准价怎么来。

先看最简单的：

```python
mid = (bid1 + ask1) / 2
```

然后再看：

```python
micro_price
depth_weighted_mid
```

你先不要一开始就纠结 micro price，它是进阶内容。

---

## 第四优先：看 `InventorySkewEngine`

这个模块是库存控制。

你重点理解：

```python
pos > 0
```

为什么报价要整体往下移。

```python
pos < 0
```

为什么报价要整体往上移。

这个搞懂后，你就明白做市商为什么不是机械挂单，而是会根据库存动态倾斜报价。

---

## 第五优先：看 `on_trade()` 和 `HedgeEngine`

这个是成交后的处理。

你要理解两个概念：

```text
报价成交 ≠ 立刻一定对冲
```

只有：

```python
enable_hedge = True
```

并且：

```python
abs(pos) >= hedge_threshold
```

才会主动对冲。

所以现在这个策略是：

> 平时靠库存偏移慢慢调仓，仓位太大时才主动对冲。

---

## 七、你现在这版代码的策略本质

这不是纯高频抢盘口策略，而是一个比较标准的：

> **基于基准价的多档双边被动做市策略 + 库存偏移 + 成交后阈值对冲。**

更直白地说：

```text
我先算一个合理中间价 fair_price。
然后在 fair_price 下方挂买单，在 fair_price 上方挂卖单。
如果买多了，就把报价往下调，让自己更容易卖出、不容易继续买。
如果卖空多了，就把报价往上调，让自己更容易买回、不容易继续卖。
如果行情质量不好、盘口太薄、价差太小、盘口失衡，就撤单不做。
如果成交后仓位超过阈值，就主动发平仓单对冲。
```

---

## 八、你最应该先画出来的流程图

你可以按这个图理解：

```text
on_tick 收到行情
    ↓
MarketDataManager 整理盘口
    ↓
QuoteRiskFilter 检查行情
    ↓
PricingEngine 计算 fair_price
    ↓
QuoteEngine 生成双边报价
    ↓
InventorySkewEngine 根据库存偏移报价
    ↓
QuoteRiskFilter 根据最大持仓过滤报价
    ↓
need_requote 判断是否需要撤单重挂
    ↓
cancel_all 撤旧单
    ↓
buy / short 发新报价
    ↓
等待成交
    ↓
on_trade 成交回报
    ↓
可选：撤单 + 主动对冲
```

## 九、最关键的一句话

你理解这段代码，不要先陷进所有类的细节里。

你先抓住：

```python
on_tick()
```

然后顺着里面调用的模块一个一个看。

因为这段代码不是“从上往下执行”的普通脚本，而是 **事件驱动策略**：

```text
行情事件触发 on_tick
订单事件触发 on_order
成交事件触发 on_trade
停止单事件触发 on_stop_order
```

所以你真正要理解的是：

> 每个事件来了以后，策略做什么。
